## Selected Projects

The projects below were developed collaboratively as part of FIAP postgraduate and technology challenges. The team participated throughout the lifecycle — planning, architecture, documentation, development and deployment. My contributions have been especially focused on **architecture, infrastructure and system integration**.

### 1. Restaurant Management API
**Java 17 · Spring Boot · Spring Security · JWT · MySQL · Docker**

A RESTful backend for a restaurant platform, covering user management, role-based access, customer and restaurant-owner profiles, and address management.

**Engineering highlights**
- JWT-based authentication and authorization with Spring Security.
- Layered architecture, DTOs, dependency injection and repository pattern.
- Relational persistence with JPA and MySQL.
- Containerized local environment with Docker Compose.

[Repository](https://github.com/gf-filipe/tech-challenge-fase-01)

### 2. Restaurant & Menu Management
**Java 17 · Spring Boot · Clean Architecture · MySQL · H2 · Docker**

An evolution of the restaurant domain, with restaurant registration, menu management, user roles and protected operations.

**Engineering highlights**
- Clean Architecture separation across domain, use cases, gateways and infrastructure.
- JWT authentication and role-based endpoint protection.
- Persistence adapters and mapping between domain and JPA models.
- OpenAPI documentation and automated tests.

[Repository](https://github.com/gf-filipe/tech-challenge-fase-02)

### 3. Order Processing with Microservices
**Java · Microservices · Apache Kafka · Resilience4j · MySQL · Docker Compose**

An online ordering system split into authentication, order and payment services, using asynchronous messaging to coordinate the order lifecycle.

**Engineering highlights**
- Event-driven communication through Apache Kafka.
- Separate services for authentication, order management and payment processing.
- Resilience patterns including circuit breaker, retry and timeout with Resilience4j.
- Asynchronous handling and reprocessing of pending payment events.

[Repository](https://github.com/gf-filipe/tech-challenge-fase-03)

### 4. Serverless Feedback Platform
**Java 17 · Quarkus · PostgreSQL · Azure Functions · GitHub Actions**

A feedback platform that uses a Quarkus REST API and Azure Functions to process urgent notifications and scheduled reports.

**Engineering highlights**
- Serverless functions designed around distinct responsibilities.
- Azure Consumption Plan to support usage-based execution.
- CI/CD pipeline with GitHub Actions, including build and test gates before deployment.
- Health checks, Azure Monitor and Application Insights for operational visibility.
- Defensive fallback behavior for notification delivery failures.

[Repository](https://github.com/gf-filipe/tech-challenge-fase-04)

### 5. SUS Connect
**Java 21 · Spring Boot · PostgreSQL · Apache Kafka · Machine Learning · Docker**

A healthcare scheduling platform developed during the FIAP postgraduate hackathon to help reduce unused appointment slots through patient confirmations, cancellation workflows and no-show risk estimation.

**Engineering highlights**
- Appointment confirmation workflow across simulated WhatsApp, SMS and email channels.
- Kafka-based event processing for released appointment slots.
- Integration with a machine-learning component for no-show risk estimation.
- Clean Architecture, DDD concepts and application-level CQRS separation.
- Docker Compose environment for the application and supporting infrastructure.
- Automated test suite documented in the project README.

[Repository](https://github.com/gf-filipe/sus-connect-api)
